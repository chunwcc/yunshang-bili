# 竖屏沉浸流（上/下滑切视频）方案

> **2026-10-30 视觉改版（v2）**：覆盖层按手绘稿重做——中间内嵌视频卡 + 三组沉浸光感胶囊
> （左上 UP/关注、右上 点赞/投币/收藏、下方 返回/发弹幕/弹幕开关/评论区/全屏）。
> 新设计稿：`design/关灯短视频-沉浸胶囊版.html`。
> 本方案的播放/换源/预取/心跳架构不变；下文的 UI 落点（右侧竖排互动栏）以 v2 为准。

> 目标：像抖音那样上下滑切换视频，尽量复用现有「关灯」模式。
> 结论：**可行，建议做成「关灯」的子状态，而不是新建一个播放页。**
> 设计稿：`design/vertical-feed.html`（可交互，含标注、横屏/加载态、规格面板）

---

## 1. 结论与边界

### 能做成什么样

- 关灯状态下，**上滑下一条、下滑上一条**，跟手位移 + 越过阈值吸附。
- 单条视频仍然走现有的完整链路：详情 → playurl → DASH 转播站 → AVPlayer → 弹幕 → 心跳/历史。
- 上滑时下一条先以**封面 + 模糊背景 + 标题**露出，切过去后首帧淡入；不会出现两条视频同时解码。
- 双击点赞、长按 2×、单击暂停、底部进度条拖动 seek、右侧互动栏。
- 退出沉浸流 → 回到**当前这条**的关灯详情页（不是最初那条）。

### 明确不做（第一版）

- 不做多 `XComponent` / 多 `AVPlayer` 的「无缝双播」。
- 不做 PGC（番剧/影视）混排；feed 只收 UGC 的 `av` 卡片。
- 不做半屏评论面板；评论按钮先「退出沉浸流 → 打开该视频详情评论区」。
- 不改现有详情页、评论区、选集、全屏等布局。

### 为什么不做「新建 VerticalFeedPage」

`VideoPlayerPage.ets` 已经踩完了这条链路上的坑：playurl 的 v_voucher 风控、DASH 转播站、
`prepared → 首帧` 的等待、续播 seek、弹幕分段、心跳 5 秒闸、后台播放/画中画。
新建页面要么复制一遍（等于重踩），要么先把播放器抽成服务（大重构，回归面不可控）。

## 2. 现有关灯给了我们什么

| 现成能力 | 位置 | 沉浸流怎么用 |
|---|---|---|
| 单实例 `XComponent`，跨布局常驻 | `VideoPlayerPage.ets:8369` | 换条只换 `AVPlayer` 数据源，Surface 不重建 |
| 关灯视频 fit 放大 | `loVideoWidth/loVideoHeight` `:399` | 竖向视频铺满；横屏视频上下留黑 |
| 关灯模糊封面背景 + 0.72 压暗 | `:10514` | 横屏视频的 letterbox 背景 |
| 常驻层几何（矩形 / 视频尺寸） | `ovRect*` `:432`、`ovVideo*` `:462` | feed 模式强制成「整窗 + fit」 |
| 播放器初始化（含自动起播） | `initP()` `:4795`，`prepared` 分支 `:4965` | `loadFeedItem` 直接复用 |
| 弹幕（含 cid 变化重载） | `DanmakuView` `:18`、`:245`、`:278` | 换条时重载弹幕 |
| 观看历史/心跳 | `saveWatchHistory()` / `reportWatchBehavior()` `:3499` | 切条前先落库 |
| 相关推荐 / 推荐流 | `getRelatedVideos`（`BilibiliApi.ets:3194`）、`getRecommendVideosOptimized`（`RecommendApiOptimized.ets:129`） | feed 数据源 |

**一个硬约束**：整个页面只有一个 Surface。相邻页只能渲染封面，不能挂第二个 `XComponent`。
这也是「单实例换源」方案的核心前提。

## 3. 交互设计

### 3.1 手势

| 手势 | 行为 | 判定 |
|---|---|---|
| 上滑 | 下一条 | `-dy > 0.16 * ch` 或 `velocityY < -500 vp/s` |
| 下滑 | 上一条 | 同上反向 |
| 首条下滑 | 橡皮筋回弹；超过 `0.3 * ch` 松手退出沉浸流 | 阻尼系数 0.35 |
| 单击画面 | 暂停 / 继续 | 延迟 260ms，等双击判完 |
| 双击画面 | 点赞 + 心形爆裂 | 取消单击计时 |
| 长按画面 | 2× 倍速 | 沿用现有 `onTD` 长按逻辑 |
| 底部进度条 | 拖动 seek | 热区 18vp，条高 3vp |
| 返回 / 左上 | 退出沉浸流 → 关灯详情（当前条） | 先退 feed，再按原有关灯返回逻辑 |

⚠️ **必须处理的手势冲突**：现有 `onTM`（`:6558`）在竖向拖动时会进入音量/亮度。
feed 模式要在 `onTM` 里提前 `return`（或 `gm_ = 'feed'` 并在各分支跳过），
否则上滑会被亮度手势吃掉。

### 3.2 进入 / 退出

- **进入**：关灯状态下上滑；或关灯 HUD 里的「沉浸流」按钮；或在首页/播放页加显式入口。
- **退出**：返回键 / 左上返回 / 首条继续下滑。退出后停在**当前条**的关灯详情页，
  `vd` 已经在 feed 过程中拿到了，只需补 `pendingCommentAid`，不用重新请求详情。

### 3.3 状态机

```
idle
  └─ prefetching  （当前条播放中，静默预取下一条 detail + playurl）
       └─ ready   （封面已解码、playurl 已到）
            └─ playing ⇄ paused
                 └─ swapping （手指抬起 → 280ms 位移 → 换源）
                      └─ playing
任一环节失败 → error（封面 + 重试/跳过；连续失败 2 次自动跳下一条）
```

关键：**swapping 时先藏旧画面，再改 `vi`**。否则会闪回上一帧。

## 4. 数据流

### 4.1 feed 来源

1. 以当前视频为种子：`getRelatedVideos(bvid)`（同题材，连续看更自然）。
2. 不够 3 条时续推荐流：`getRecommendVideosOptimized(freshIdx)`。
3. 过滤：只保留 `goto === 'av'`（或 `id` 是 BV 号）且 `bvid` 有效；丢掉直播、广告、番剧、课程。
4. 去重：按 `bvid`；当前视频也在集合里（作为第 0 条）。
5. 每次切条后 `addWatchedVideo(bvid)`，避免推荐又推回来。

> 第一版建议**不做时长过滤**，但留一个设置项「只看 5 分钟内」。
> 竖屏 feed 里混 40 分钟的长视频体验会很怪，等真机看效果再定默认值。

### 4.2 预取

- 当前条 `prepared` 后 **800ms** 再开始预取，避免和首帧抢网络/解码。
- 只预取**下一条**：
  - `getVideoDetail(bvid)`（已有缓存 + 进行中去重）；
  - `getVideoPlayUrl(bvid, cid, qn)`；
  - 可选：临时 `DashPlayerBridge` 预热首段（参考 `prefetchUpgradeTarget`，`:6060` 一带）。
- ⚠️ playurl 缓存 TTL 只有 **60 秒**（`BilibiliApi.ets:1156`）。预取太早会过期，
  建议给 feed 单独加一个 3~5 分钟的缓存，或切条前重新取一次。
- ⚠️ playurl 有 `v_voucher` 风控。**不要并发预取多条**，只预取下一条。

## 5. 换源流程（关键顺序）

```ts
private async loadFeedItem(i: number): Promise<void> {
  const gen = ++this.feedGen;                 // 世代号，快速连滑时丢弃旧任务
  this.flushCurrentFeedProgress();            // ① 先落库（>=5s 才发）
  this.contentVisible = false;                // ② 先藏旧画面，让封面顶上
  this.release();                             // ③ 停 AVPlayer / DASH 转播站
  if (gen !== this.feedGen) return;

  this.feedIndex = i;
  const it = this.feedItems[i];
  this.vi = { bvid: it.bvid, cid: it.cid, title: it.title, cover: it.cover };
  this.ct = 0;                                 // ④ 进度/心跳基准归零
  this.dur = 0;
  this.lastHeartbeatTime = 0;
  this.initialProgress_ = 0;                   // feed 不从续播点起播
  this.err = '';
  this.ld = true;
  this.feedDragY = 0;

  await this.fillFeedDetail(it);               // ⑤ detail（缓存命中优先）
  if (gen !== this.feedGen) return;
  await this.initP();                          // ⑥ 取 playurl → 转播站 → 自动起播
}
```

`initP()` 内部在 `prepared` 时会 `play()` 并把 `contentVisible = true`，
所以第 ② 步的封面会一直显示到首帧，起播后淡入，不需要额外控制。

### 进度落库

```ts
private flushCurrentFeedProgress(): void {
  // saveWatchHistory 内部已有 MIN_HEARTBEAT_PROGRESS_SEC 闸，但这里再判一次更直观
  if (this.ct >= MIN_HEARTBEAT_PROGRESS_SEC) {
    this.saveWatchHistory();     // 写 B 站历史
    this.reportWatchBehavior();  // 行为上报（UGC）
  }
  this.stopHeartbeat();
  this.startHeartbeat();         // 换成新条的基准
}
```

⚠️ 顺序不能反：**必须在改 `vi` / `release()` 之前调用**。
否则 `ct` 被重置成 0，上报就变成「把已有进度清零」——这条在 AGENTS.md 里已经踩过两次。

## 6. UI 落点

### 6.1 几何

feed 模式下覆盖层必须是**整窗**，否则还是「视频槽」大小，HUD 会被 `clip(true)` 裁掉：

```ts
private ovRectX(): number { if (this.isFeedMode) return 0; /* 原逻辑 */ }
private ovRectY(): number { if (this.isFeedMode) return 0; /* 原逻辑 */ }
private ovRectW(): number { if (this.isFeedMode) return this.cw; /* 原逻辑 */ }
private ovRectH(): number { if (this.isFeedMode) return this.ch; /* 原逻辑 */ }
```

视频尺寸仍走 `loVideoWidth/loVideoHeight`（fit + 12 安全边距）。
横屏视频的模糊背景放在覆盖层内部（当前条），不要用页面级 `lightsOffBgSrc()`——
那个背景不会跟着手指走。

### 6.2 页面栈

```ts
Stack() {                       // buildPlayerOverlay 根节点
  // 下一条（+ch）、上一条（-ch）只渲染封面 + 标题骨架，不挂 XComponent
  FeedPageView({ item: prev, offset: -ch })
  FeedPageView({ item: next, offset: +ch })
  // 当前条：封面（未起播时）+ 视频 + 弹幕 + HUD
  ...
}
.translate({ y: this.feedDragY })   // 整层跟手
```

提交时：`dragY → ±ch`，动画结束的同一帧里 `feedIndex += dir; dragY = 0`，
因为相邻页的相对位置同步重算，视觉上不会跳变。
**不要移动 `XComponent` 的宽高**，只做 `translate`，避免 Surface 重建。

### 6.3 新组件 `FeedOverlay`

只吃 props，不碰播放器：

```
topbar        返回 / 「关灯 · 沉浸流」胶囊 / 弹幕开关 / 更多
right rail    头像+关注 / 点赞 / 投币 / 收藏 / 评论 / 分享
meta          @UP + 关注、标题 2 行、标签、播放量 · 弹幕数 · 时间
progress      3vp 细条 + 时间，热区 18vp
center        暂停时的大播放键；loading 时 spinner
burst         双击点赞的心形爆裂
```

现有 `VideoControls` 有 2600+ 行、强依赖全屏/横屏状态，**不建议塞 feed 皮肤**；
新建一个轻量 HUD 反而更快、更安全。

## 8. 风险清单（按优先级）

1. **心跳清零**：切条前必须 `saveWatchHistory()`；`<5s` 一律不发。
   参考 AGENTS.md「PGC 心跳两条铁律」。
2. **单 Surface**：相邻页只渲染封面；不要试图挂第二个 `XComponent`。
3. **弹幕串台**：`DanmakuView` 只在 duration 变化时重载；两条视频时长恰好相同会串。
   给 `cid` 加 `@Watch`，显式 `reinitializeDanmaku()`。
4. **快速连滑竞态**：`initPInProgress_` 会让第二次 `initP` 直接 return。
   用 `feedGen` 世代号，每个 `await` 后校验；最后一次为准。
5. **覆盖层几何**：feed 模式必须整窗，否则 HUD 被裁；`clip(true)` 不会报错，只会神秘消失。
6. **playurl 60s 缓存**：预取太早会过期；只预取下一条，避免风控。
7. **LiveViewHelper**：`setupL` 的 `prepared` 分支每次都会 `LiveViewHelper.create`。
   切条前先 `LiveViewHelper.end()` 或加「只创建一次」的守卫，避免实况窗泄漏。
8. **自动画中画**：`release()` 会解除武装；feed 切条期间回桌面不应该拉起旧视频的小窗。
9. **弹幕画布**：feed 模式画布 = 视频区；横屏视频的外置弹幕在视频下方，
   要确保右侧内缩 56、底部不压信息区。
10. **退出沉浸流**：`vd` 是当前条的；退出后要补 `pendingCommentAid` 和评论游标，
    不能还留着上一条的评论数据。
11. **屏幕旋转 / 窗口变化**：feed 是竖屏体验，进入时锁竖屏（或旋转即退出并回详情）。
    否则会半途切到 `buildLandscape` / `buildLandscapeVertical`，覆盖层几何和手势全部对不上。

## 9. 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 关灯子状态 + 单实例换源** | 复用全部播放链路；无第二 Surface | `VideoPlayerPage` 状态多，需要严格的 reset 顺序 | ✅ 推荐 |
| B. 新建 `VerticalFeedPage` | 隔离干净 | 复制 playurl/DASH/弹幕/心跳，或先抽播放器服务 | ❌ 第一版不做 |
| C. `Swiper` + 每页一个 `XComponent` | 天然跟手、可预播 | N 个解码器 + N 个弹幕画布；4K DASH 直接爆内存 | ❌ 不推荐 |
| D. `Swiper` + 单播放器迁入当前页 | 视觉最接近抖音 | 播放器要在页面间搬移，Surface 生命周期风险高 | ⏳ 以后再说 |

## 10. 需要拍板的产品问题

1. **入口**：只做「关灯上滑进入」，还是首页/播放页也加入口？
2. **内容范围**：只 UGC，还是要把番剧/影视也混进来？（第一版建议只 UGC）
3. **时长过滤**：是否默认「只看 5 分钟内」？
4. **评论**：点评论是退回详情页，还是做半屏评论？
5. **弹幕**：竖屏 feed 默认开还是默认关？（B 站用户可能希望开）
6. **播放结束**：循环当前条，还是自动下一条？
7. **横屏视频**：保留 letterbox，还是 feed 里只推竖屏内容？

## 11. 设计稿说明

文件：`design/vertical-feed.html`

- 左侧是 **440 × 707 vp** 的可交互原型（与真机 1320 × 2120 @3x 一致）。
- 支持：拖动屏幕 / ↑↓ 切换、空格暂停、D 弹幕、A 标注、双击画面点赞、底部进度条拖动。
- 工具条可跳到「横屏示例」「加载态」，用来检查两种特殊布局。
- 右侧是交互映射、视觉规格、状态机、实现落点、风险清单与排期。
- 视频画面用 CSS 场景占位，不依赖任何外部图片；直接双击 HTML 即可打开。

> 设计稿是「视觉与交互基线」，不是最终像素。真机上需要按 `cw/ch/safeCM()` 的
> 实际值再调一轮边距和字号。
